# Trajectory Denoising Autoencoder

## Project Description

Thesis project investigating **denoising of 3D spiral trajectories using a
fully-connected (dense) autoencoder in PyTorch**. Synthetic 3D spiral
("circular motion") trajectories are generated with randomized physical
parameters (starting radius, radius growth rate, vertical speed, arc length),
corrupted with i.i.d. Gaussian noise, and a denoising autoencoder is trained
to map the noisy trajectory back to its clean counterpart.

The project includes:

- Synthetic spiral trajectory generation with a controllable, low intrinsic
  dimensionality (4 physical parameters per trajectory).
- A configurable Gaussian noise injection model.
- A fully-connected denoising autoencoder (`Linear -> ReLU` encoder/decoder)
  with early stopping.
- An evaluation and visualization suite: loss curves, reconstruction overlays,
  per-axis time series, residual plots, MSE distribution, SNR improvement,
  PCA of the latent space, and encoder weight heatmaps.
- Ablation scripts sweeping the bottleneck (embedding) size and the noise
  level to characterize the capacity/noise-robustness tradeoff.

See [`ARCHITECTURE.md`](ARCHITECTURE.md) for the full module-by-module
breakdown and the mathematical model. See the included PDFs
(`AE_analysis.pdf`, `AE_Mathematical_Foundations.pdf`) for a written analysis of
experimental results.

## Technology Stack

| Layer | Technology |
|---|---|
| Language | Python 3.11 |
| Deep learning framework | [PyTorch](https://pytorch.org/) (`torch`) |
| Numerical computing | [NumPy](https://numpy.org/) |
| Plotting / visualization | [Matplotlib](https://matplotlib.org/) (incl. 3D axes, animation writer) |
| Model summary | [torchinfo](https://github.com/TylerYep/torchinfo) |
| Computation graph visualization | [torchviz](https://github.com/szagoruyko/pytorchviz) + [Graphviz](https://graphviz.org/) (system binary) |
| Model interchange / graph inspection | [TorchScript](https://pytorch.org/docs/stable/jit.html) export (`.pt`) viewable in [Netron](https://netron.app) |

No GPU is required — the project runs on CPU (`torch` CPU build). CUDA is
used automatically if available (`main.py` selects `cuda` when
`torch.cuda.is_available()`).

## Requirements

- **Python**: 3.11 (developed and tested on 3.11.9)
- **System dependency**: [Graphviz](https://graphviz.org/download/) (the
  `dot` binary) must be installed and on `PATH` for the `torchviz`
  computation-graph export in `main.py` to work. On Windows,
  `winget install Graphviz.Graphviz` installs it to
  `C:\Program Files\Graphviz\bin` (main.py adds this path automatically as a
  fallback if it isn't already on `PATH`).
- **Python packages**: see [`requirements.txt`](requirements.txt).

### Setup

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS/Linux
source .venv/bin/activate

pip install -r requirements.txt
```

### Running

```bash
# Full training run: generates data, trains the AE, saves all plots/artifacts
# to results/<timestamp>_.../
python main.py

# Ablation: test MSE vs. bottleneck (embedding) size
python bottleneck_ablation.py

# Ablation: test MSE vs. noise level (sigma)
python noise_sweep.py

# Inspect a saved dataset sample (after running main.py at least once)
python inspect_data.py [sample_idx] [--csv]
```

Hyperparameters (`N_TRAJECTORIES`, `T`, `NOISE_SIGMA`, `EMBEDDING_SIZE`,
`EPOCHS`, `BATCH_SIZE`, `LR`, `TRAIN_SPLIT`) are set as constants at the top
of `main.py` (and similarly in the ablation scripts).

Generated datasets (`data/`) are not tracked in git and are regenerated by
running the scripts above. Per-run results (`results/`) are tracked in git so
past runs' plots, animations, and exported models remain available without
re-running training.
